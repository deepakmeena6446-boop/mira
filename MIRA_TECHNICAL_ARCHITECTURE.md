# MIRA — V0 technical architecture

**Source of truth for how to build.** The workspace was empty on 2026-09-24: no Git repository, code, schemas, scripts, tests, deployment config, or environment files. This document proposes a small monolith plus one reliable worker. It does not authorize implementing a different product. Reconcile behavior with `MIRA_PRODUCT_SPEC.md` and screens with `MIRA_UX_UI_SPEC.md`.

## 1. Stack and repository shape

Use **Next.js App Router + TypeScript** for web UI and same-origin HTTP route handlers, **PostgreSQL + PostGIS** for durable private data and spatial queries, **Drizzle ORM** for ordinary schema/query work plus reviewed SQL migrations for PostGIS, **MapLibre GL JS** for the map, **Vitest + Testing Library + Playwright** for tests, **Docker Compose** for local PostGIS and Mailpit, and a separate **Node worker process in the same repository** for time-based jobs. Deploy web and worker with the same code/version against one database. This is one application, not microservices. Pin stable package versions and commit a lockfile during Phase 0; use an LTS Node release supported by selected dependencies. Next.js supports a Node server deployment; do not use static export or serverless-only hosting for journeys that require the worker. [Next.js deployment documentation](https://nextjs.org/docs/app/getting-started/deploying).

Expected shape: `src/app` (screens and API), `src/components` (shared UI), `src/domain` (pure validation, journey transitions, aggregation rules), `src/server` (DB, auth, encryption, repositories, integrations), `src/worker` (polling jobs), `db/migrations`, `scripts/import-pilot.ts`, `data/pilot` (sourced manifest/extract artifacts), `tests`, `docker-compose.yml`, `.env.example`. The code may adjust folder names for framework conventions but preserve boundaries. Use server-only modules for secrets. No browser bundle contains DB, AI, SMTP, or encryption keys.

## 2. Pilot map and Day-1 KNOW

Pilot: Delhi University North Campus/Vishwavidyalaya Metro ecosystem, fixed bounding rectangle **south 28.6850, north 28.7050, west 77.2020, east 77.2250** (WGS84). Phase 0 commits `data/pilot/manifest.json` with this boundary, download URL, extraction date, source licence, importer version, and checksums. Obtain a **real** OSM extract once during setup, rather than live geocoding or per-user Overpass calls. If the source is temporarily unavailable, complete other phases and leave the import command/retry path; do not substitute fictional production data. Public Overpass instances have limited capacity; prefer a small permitted extract, cache it, and use one-time import. [OSM download guidance](https://wiki.openstreetmap.org/wiki/Download), [Overpass guidance](https://wiki.openstreetmap.org/wiki/Overpass_API).

Import named places (metro entrances, shops with relevant tags, pharmacies, public facilities) and foot-permitted walkways. Validate geometry, deduplicate IDs, reject missing/invalid coordinates, and record source tags and snapshot date. Do not infer unrecorded lighting, operating status, crowd presence, or accessibility. Store place index and a directed walking graph; split at intersections; respect `foot` restrictions and one-way pedestrian rules; reject disconnected/invalid edges. Route with A* or Dijkstra using length as cost and a documented walking speed of 4.5 km/h. Snap origin/destination to nearest walkable graph node only within a bounded radius (e.g. 100 m); otherwise return no route. Provide shortest path and at most one truly distinct alternate: penalise shared edges, require at least 20% different edge length and no more than 1.5× the shortest distance. Never use a safety weight. Route evidence intersects coarse cells, not individual reports. Route results are calculated server-side and not persisted per user.

Use MapLibre with a configurable raster tile URL, defaulting to OSM standard tiles for low-volume interactive pilot use only. Keep visible © OpenStreetMap contributors attribution, a valid browser Referer, normal caching, no prefetch/offline tile downloads, and a provider switch before scale. If tiles fail, retain list-based evidence. Do **not** call public Nominatim for autocomplete; local indexed search avoids rate/usage limits and sending queries out. [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/), [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/), [MapLibre raster example](https://maplibre.org/maplibre-gl-js/docs/examples/map-tiles/).

## 3. Data model and privacy boundaries

Use UUID primary keys and UTC timestamps. Store geometry in WGS84; use PostGIS `geography` for metre-distance queries where needed ([PostGIS `ST_DWithin`](https://postgis.net/docs/ST_DWithin.html)). Migrations are forward-only and reviewed by the main implementer.

| Table | Required fields | Access / retention |
|---|---|---|
| `pilot_areas` | id, name, polygon, source_date, manifest_hash | Public pilot metadata. |
| `places` | id, osm_type/id, name, point, type, selected OSM tags, source_date | Public, only licensed/source-labelled fields. |
| `walk_nodes`, `walk_edges` | node point; directed edge from/to, geometry, metres, source_id, walkability tags | Public-derived route graph; no user data. |
| `actor_sessions` | hashed random cookie token, created/expires | Private pseudonymous access, rotate/expire after 30 days; no profile. |
| `reports_private` | id, actor_hash, category, experienced/witnessed, coarse_cell_id, recency_bucket, time_band/unsure, encrypted_text, redaction_flags, status, created_at, reviewed_at, expires_at | Moderator only; hard delete at 30 days (or sooner on rejection/request). No exact report coordinate or precise incident timestamp is collected. |
| `report_structured` | report_id, approved category/tags, cell, time_band, approved_at, duplicate_group | Private input to aggregation; hard delete with report after 30 days. |
| `aggregate_releases` | id, weekly_release_at, cell, time_band, category/tag set, qualitative copy, source date band, expires_at | Only this table feeds public community output; expiry after 35 days. No exact counts or narratives. |
| `journeys` | id, owner_actor_hash, encrypted destination label, optional place_id, ETA, state, contact_state, created/closed/purge timestamps, one-alert marker | Private; no location track. Hard delete within 24h of closure. |
| `contact_invites` | journey_id, token hash, encrypted email, accepted_at, revoked_at, expires_at | Private; token single journey and expires at journey close; hard delete with journey. |
| `admin_sessions` | hashed token, expiry | Admin only, short-lived (e.g. 12h); no persistent personal user profile. |
| `abuse_counters` | daily HMAC of IP/actor, bucket, count, expiry | Private operational data, 24h expiry; never raw IP in DB. |

`actor_sessions` are only a browser ownership mechanism. Clear cookie on expiry. A missing cookie cannot retrieve an existing journey; no account recovery V0. Avoid storing origin when creating journeys; destination can be a place ID and optional minimised label. Exact private destination text and contact email use application-level AES-256-GCM with a secret outside source control. TLS and database disk encryption are deployment requirements. Do not put sensitive data in logs, traces, URLs, client persistence, analytics, or backups beyond the defined retention; configure backup expiry at or below 30 days and document restore-time purge. Log IDs/state transitions without narrative, contact email, coordinates, or token.

## 4. APIs and authorization

Use server-validated schemas for every body and response. Same-origin cookie with `HttpOnly`, `Secure` in production, `SameSite=Lax`; CSRF protection for state-changing cookie-authenticated requests (Origin check plus token or equivalent). Rate limit report, journey, invite, and admin login endpoints. Reject oversized bodies. No CORS exposure by default.

| Endpoint | Function | Access / response boundary |
|---|---|---|
| `GET /api/pilot`, `GET /api/places?q=`, `POST /api/know` | Pilot metadata, local place search, place/route evidence | Public; only sourced facts and released aggregates; no raw reports or per-user data. `POST` avoids coordinate URLs. |
| `POST /api/reports/suggest`, `POST /api/reports` | Optional consented AI suggestions without persistence; then validate, minimise, encrypt, queue private report | Anonymous actor cookie; suggestions are private/ephemeral and final submit returns opaque receipt only. |
| `POST /api/journeys`, `GET /api/journeys/current` | Create/read own temporary journey | Owner actor cookie; no public journey endpoint. |
| `POST /api/journeys/:id/arrive`, `/end`, `/extend`, `/revoke-contact` | Atomic state transitions | Owner only; idempotent as appropriate. |
| `GET /invite/:token`, `POST /api/invites/accept` | One-journey contact consent | GET exchanges token for short-lived HttpOnly invite cookie and redirects to clean `/invite`; POST uses cookie. Token grants only acceptance, never live location or route; hashed at rest. |
| `POST /api/admin/login`, `POST /api/admin/logout`, `GET /api/admin/reports`, `GET/PATCH /api/admin/reports/:id` | Minimal moderation | Admin session only; private report access, structured edits and decisions. |
| `GET /api/health/live`, `GET /api/health/ready` | Process and DB/worker readiness | No secret details. Journey creation checks worker heartbeat. |

Only `aggregate_releases` may be joined into public KNOW responses. Add automated contract tests that request every public endpoint and assert absence of private table fields. Admin methods require a password hash (Argon2id) supplied via `ADMIN_PASSWORD_HASH`; no default password. Failed attempts are throttled. An admin session is separate from an actor session. No user-facing login or contact dashboard.

## 5. REPORT pipeline, AI, and moderation

Submission: validate fields and pilot cell → normalise text → deterministic PII scanning (email, phone, plate-like strings, URL/social handles, address patterns) → replace detected spans in any AI input → encrypt original private text → flag uncertain content for review → save `pending` or `held`. Do not publish directly. An idempotency key prevents duplicate submit on retry. Reports without narrative still work. Reject direct identifiers in structured tags. Duplicate hints use same actor/cell/category/time bucket plus normalised text fingerprint; hints are for moderation, not truth judgements.

Optional AI adapter: only after explicit report-level consent, and only when `OPENAI_API_KEY` and `OPENAI_MODEL` are configured. The rate-limited `/api/reports/suggest` call occurs on the editable review screen before final submission; it does not persist the draft. Send minimised, pre-redacted text, no exact coordinates/contact, with `store:false` on the Responses API. Require a strict structured output schema for suggested category/tags and explicit `unknown` values; validate again server-side and present suggestions for user edit/moderator review. Do not use AI output as a privacy or publication authority. Provider failure/timeouts fall back to manual fields without losing the report. Official OpenAI documentation supports structured outputs and shows that Responses API default storage differs when `store:false` is used; its abuse-monitoring retention can still apply. Show this third-party processing in consent text and do not enable the adapter until its privacy terms are accepted for the deployment. [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [data controls](https://developers.openai.com/api/docs/guides/your-data).

Admin review: open only authorised detail, inspect redaction flags/duplicate hints, edit structured fields, then approve for **aggregation only**, hold, or reject. Approval stores no public narrative. The worker aggregates approved, nonduplicate reports in fixed 500 m grid cells, `day` (06:00–18:00), `evening` (18:00–22:00), `late` (22:00–06:00) IST; `unsure` is excluded from time-specific release. `today`/`yesterday`/`past week` reports may count if submitted within 21 days before release, so even a report of a past-week event refers to the prior 28 days; `earlier/unsure` remains private but is not counted because freshness cannot be established. Release each Monday only when at least five independent actor hashes contribute to a cell + time band + category, and at least five *new* independent contributors exist since a changed public release for that key. Never reveal exact counts; use fixed factual templates such as “Multiple reviewed observations mention poor lighting in this area during late hours.” If categories are too granular to pass threshold, do not combine unrelated categories merely to publish. Check burst patterns and duplicate groups before counting. Positive conditions appear separately. A release expires after 35 days and is not updated midweek; withdrawal suppresses future releases and may emergency-remove a release if privacy is at risk. Tests must check threshold, duplicates, weekly cadence, differencing, expiry, and time-band isolation. These are V0 design constants; operational abuse heuristics need not be public in the app.

## 6. Journey state machine and worker

States: `active` → `arrived` or `ended`; `active` → `missed` at ETA+10m; `missed` → `arrived` or `ended` on user action, otherwise `expired` at ETA+30m. An `active` journey may extend ETA once before miss, within the 4h maximum from creation. Terminal states cannot reopen. Creation requires one active journey per actor. Use DB transactions/conditional updates so a racing arrive and missed job cannot both win. Store an alert attempt marker; one SMTP attempt maximum. The worker polls due rows at least once per minute using row locking, updates status, and atomically claims an alert attempt only for an **accepted, unrevoked** invite. It then sends one email and stores the SMTP outcome. A crash after claim may leave delivery `unconfirmed`; do not retry an ambiguous attempt or claim success. A definite SMTP failure is shown as failed. This at-most-once design avoids duplicate alerts but cannot guarantee delivery; the UI must say so. Email content includes ETA and a public place name only if selected from the place index; for manual/private labels use “planned destination.” Poll closed/expired rows and hard-delete journey/contact data by `purge_at` within 24h. Worker heartbeat every minute; readiness becomes unhealthy if stale for 3 minutes. Use a deterministic injectable clock for tests.

SMTP email is the only V0 automatic contact channel. Invite link has a cryptographically random token, stored hashed, HTTPS in production, one journey scope, and cannot be used to request live location. The landing handler exchanges it for a short-lived HttpOnly cookie and redirects to `/invite` before rendering; send no third-party requests from the token URL, set `Referrer-Policy: no-referrer`, and redact token from access logs. A forwarded link remains a bearer invitation in V0; explain this limitation in the invite copy. Mailpit captures emails locally. If SMTP is absent in production, contact controls and promises are disabled; a check-in-only journey is allowed if worker readiness/deletion still function. No SMS/phone, push guarantee, emergency dispatch, or tracking. Never send email without contact acceptance. Minimise subject/body; no origin or exact route. Monitor delivery errors operationally without contact data in logs.

## 7. Environment and local setup contract

Required `.env.example` variables: `DATABASE_URL`, `APP_BASE_URL`, `SESSION_SECRET` (32+ random bytes), `DATA_ENCRYPTION_KEY` (32-byte key encoding documented), `ADMIN_PASSWORD_HASH`, `PILOT_MANIFEST_PATH`, `MAP_TILE_URL`. Optional: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`; `OPENAI_API_KEY`, `OPENAI_MODEL`. Never commit actual secrets. Validate required vars at startup; fail clearly. AI and SMTP optionality changes UI capability flags from the server. A production deployment requires HTTPS, web+worker services, PostGIS, secret storage, backup purge policy, and monitoring of worker heartbeat and mail failures.

Local commands to implement and document in package scripts: `docker compose up -d` (PostGIS + Mailpit), `npm install`, `npm run env:local` (generate ignored `.env.local` with random session/encryption secrets, Mailpit settings, and a random local admin password hash; reveal password only locally once), `npm run db:migrate`, `npm run pilot:import`, `npm run dev` (web), `npm run worker:dev` (second terminal), `npm test`, `npm run test:e2e`, `npm run build`, `npm run start`, `npm run worker:start`. Production secrets must be supplied through deployment secret storage, never generated into source control. Provide a local fixture that is **clearly test-only** so tests do not depend on network; the running app must use the sourced pilot import. If the import lacks a real snapshot, the app reports unavailable map data.

## 8. Test strategy and deployment gates

Pure unit tests: route graph, time bands, PII detection, state machine, aggregation. DB integration tests: authorization, uniqueness/idempotency, worker races, deletion, admin-only access, public response shape. Playwright mobile and desktop journeys: KNOW with/without data, REPORT through moderation/release, arrival/miss/contact consent, sparse-data and malicious input. Use Mailpit for delivery assertions. Run production build and one smoke run of web+worker+DB. Inspect logs, DB rows, and public HTTP responses for PII/location leaks. Keep test fixture data out of production import path.

## 9. Constraints, impact, implementation, future path

| Constraint | Impact | Best V0 implementation | Future path |
|---|---|---|---|
| Empty workspace and no source snapshot | No existing app/data to preserve; KNOW needs real import | Bootstrap stack and small sourced OSM pilot extract; honest unavailable state if source fetch fails | Licensed provider or managed refresh pipeline when usage grows. |
| No credentials supplied | No real outbound contact email or hosted AI in a fresh checkout | Mailpit locally; SMTP/AI adapters and capability flags; manual report path and check-in-only journey work | Supply production SMTP and optional AI credentials, then run integration/privacy checks. |
| No phone/voice provider and browser speech may use remote processing | “Call Me” cannot be a reliable private phone call; report voice may violate audio minimisation | Hide phone-call promise; ship text reporting and only expose on-device voice after verification; keep optional in-app companion module only if genuinely implemented and tested | Add consented telephony/voice provider and privacy review later. |
| OSM tags are incomplete and tiles are best-effort | Cannot infer current lighting, crowds, business status, or guarantee map delivery | Label mapped facts and source age; explicit unknowns; list fallback | Add field audits and licensed data providers. |
| Anonymous actor cookie can be lost or reset | Cannot recover a journey across devices; abuse rate limit is imperfect | Clearly state browser ownership; short-lived journeys; layered rate limits and moderation | Privacy-preserving account recovery after user research. |
