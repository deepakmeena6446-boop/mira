# Target screen and state inventory

This is a **functional** screen contract. Each row includes the question, required data, actions, and empty/loading/failure/low-data/privacy states. No styling decision is implied. “Claim” always uses [08](08_INTELLIGENCE_MODEL.md).

| Screen/state | User question; key content and actions | Empty / loading / failure / low-data | Privacy |
|---|---|---|---|
| **Welcome/onboarding** | “What can Mira do?” Mission, boundaries, first intent. Continue as guest; optional account later. | No location required; unavailable provider does not block entry. | Explain location/contact/chat data at use, not blanket permission. |
| **Go home, no journey** | “I'm going somewhere—where do I start?” Intent input, quick run/walk/return/arrival shortcuts, user-approved saved plan, urgent actions. | New user sees one example, no feed; recent plan may be absent. | No passive location request or inferred routine display. |
| **Intent input / context resolution** | “What do I want to do?” Purpose, from/to or loop, date/time, mode, accessibility/cost constraints; edit assumptions. | Show partial plan with one key question; search failure allows typed place/manual context. | Explicit location and saved-place use; intent not published. |
| **Place/route search** | “Which place/entrance?” Results with source and disambiguation, choose origin/destination. | No result ≠ place absent; retry/provider status; manual label possible. | Query retention and provider transfer disclosed. |
| **Option comparison** | “Which workable choice fits?” 1–3 feasible options, duration/detour, evidence, unknowns, support options, choose/edit. | If only one option, say why; partial sources marked; failure offers retry/known facts. | No sensitive destination in analytics. |
| **Plan detail / map** | “What is this route like?” Geometry, relevant segment claims, text alternative, support spots and source/age; choose/start. | Approximate line clearly not a street route; failed layers omitted with explanation. | Location transient unless starting journey. |
| **Destination/travel planning** | “How do I arrive and leave?” Arrival point/time, first transfer, lodging access, reviewed local essentials, return leg. | Without hotel/arrival point, provide limited checklist plus one question; no invented transit. | Planned trip only saved with consent. |
| **Ready-to-start confirmation** | “What will Mira track/share?” Selected route or manual plan, ETA/check-in, recipients and delivery channel; start/share separately. | Worker unhealthy blocks monitored trip, offers unmonitored plan/map; no silent share. | Explicit recipients, token expiry and revocation. |
| **Active journey/navigation** | “Where am I in my plan?” Route/map/text, current GPS age, next step if provider supports, ETA, change/support/emergency. | No GPS shows last known time; hidden/locked warns updates may pause; route failure retains manual plan. | Live points only during chosen trip; contact view limited. |
| **Ask Mira within plan/journey** | “What should I know or change?” Intent-aware conversation with grounded claims, actions and receipts. | Model fallback supplies deterministic facts/next step; no blank chat. | Sensitive prompt handling/clear history; no raw GPS trail in model history. |
| **Change/adapt** | “My route/service/plan changed.” Changed fact, revised options, cost/ETA, recipient implication, confirm choice. | No fresh route → manual alternative/external map; do not silently overwrite. | New share/destination requires explicit confirmation. |
| **I need options** | “What can I do now?” Fast reachable support places, call/contact, replan, Emergency. | If place data fail, show contact/emergency/manual steps; no fake nearby place. | Does not automatically tell contacts or record incident. |
| **Support place detail** | “Can I actually use this place?” Route ETA, access/entrance, listed/verified hours, staffing evidence, alternative, call/directions. | Unknown access labelled; closed place not recommended; provider failure visible. | Correction is optional and private. |
| **Emergency** | “How do I call appropriate help?” Reviewed country number(s), dial action and jurisdiction caveat. | Unknown profile says number unavailable; device dialler/manual contact remains. | No automatic dispatch, recording or location transmission. |
| **Arrival/close** | “Did my journey end and who can still see it?” Check-in/end status, link revocation, delivery state, optional next leg. | Worker/network uncertainty stated; close action local/server receipt shown. | Delete live points and expire links per contract. |
| **Optional contribution/correction** | “What did I observe that helps next time?” One narrow fact question, private report option, consent, receipt/withdrawal. | Skip always available; offline queue only if encrypted and expiration defined, otherwise no local persistence. | No public identity or exact personal path. |
| **Journeys list / saved plan** | “What can I resume?” Active, explicitly saved/recent plans; resume/edit/delete. | Empty points to Go; stale evidence rechecked on reopen. | User control over saved history. |
| **You/preferences** | “What does Mira know and use?” Places, mode, consent, notification controls, location/privacy, deletion. | Sync failure does not silently change consent. | View/export/delete where supported; opt-in learning. |
| **Trusted contacts** | “Who may see a trip?” Invite/acceptance, delivery channel, per-trip selection/revocation. | No contact is valid; failed invite clearly not accepted. | Contacts encrypted, no default sharing. |
| **Global low-coverage explanation** | “What can Mira know here?” Claim-by-claim source/age/unknowns, available baseline actions. | Works during provider failure and sparse geography. | Avoid disclosing reports or other users. |
| **Inbox/notifications** | “What happened to my trip/share?” Only actionable delivery/check-in changes and chosen alerts. | Empty is quiet; push failure retains in-app state. | Notification previews omit location/destination. |

**Cross-screen states:** loading must identify which check is pending; partial must not masquerade as complete; retry must preserve the entered plan; source labels need accessible text; no screen may turn a failed or empty lookup into “safe.”

## Phase 1 implementation state (2026-10-02)

`/plan` is the current transient intent entry. A guest can enter purpose, named origin, named destination or loop, local departure time with IANA zone, mode and optional constraints. Each named place stays unresolved until the person selects a search candidate; empty and failed lookup keep the typed text and offer retry. “From here” is the only plan control that requests device position. The draft survives Today, Around, map and Mira navigation, browser back and reload in the same tab, expires two hours after the last edit, and has an explicit Clear plan control.

Today links to `/plan`; Around and map use the plan's named origin and destination instead of substituting “near me.” Their existing no-plan routes remain available after Clear plan. A future or remote plan stays a plan until the person reaches its time and origin. Grounded Ask was added in Phase 3; a confirmed walking journey start was added locally in Phase 4.

## Phase 2 implementation state (2026-10-02)

Around and map now share a transient planned-option check from `/api/plan/options`. The endpoint compares actual edges in the imported OSM walking graph if its source snapshot is at most 365 days old. A distinct alternate appears only if the graph router finds one. The card names its source, snapshot date, route scope, estimated minutes and distance; the map draws the selected graph path and no estimated straight line. Daylight at departure is a NOAA-equation calculation labelled approximate; twilight, DST ambiguity and unsupported polar latitudes remain unknown. Ride/transit planned-time service, lighting and opening hours are explicitly unverified. A loop or unresolved named place receives an actionable gap statement. Missing graph, no connected path, stale snapshot and failed graph check have separate messages. No planned route trace is stored by this endpoint.

## Phase 3 implementation state (2026-10-02)

Ask accepts a guest planning question without sign-in or device location. It saves conservative explicit wording as a partial tab plan, leaves time/zone blank, gives one useful partial answer and asks one place question. A selected plan is answered through the same Phase 2 resolver, with source/age/scope in text and an accessible evidence card linking to plan edit or Around. These plan turns are not saved to the legacy chat history. An urgent phrase produces Emergency before any graph or model check. Legacy signed-in chat remains for non-plan questions. Ask cannot autonomously start/share; the map offers a separately confirmed Phase 4 journey action.

## Phase 4 local implementation state (2026-10-02)

The map offers “Start chosen walk” only for a mapped option, then a separate confirmation naming whether Circle will be notified. An unmapped walking loop instead shows calculated daylight, unknown lighting/activity, a user-chosen check-in interval and a manual check-in-only start with an explicit no-route/no-auto-arrival warning. Both start actions request a fresh position and check planned time/origin proximity before POST. A rejected check leaves the plan intact. Planning needs no account or GPS, but starting a monitored journey currently requires sign-in and a fresh device position. Circle defaults to “Just me”; the trip API also defaults omitted `share` to false. The active screen reports device fix age/accuracy, last upload age, visibility and worker state. On resume it restarts the foreground watch and refreshes the trip. Approximate provider geometry is not drawn as a street route. “I feel unsafe” presents hours/source uncertainty, route-unverified Help Point candidates, contact/share actions and direct Emergency; stale device location suppresses candidate ranking. A candidate destination change asks for a manual check-in interval and confirmation. A current-route review uses OSM graph evidence and needs confirmation before changing ETA. Local browser tests passed; real phone behavior remains unverified.

## Phase 5 local implementation state (2026-10-02)

The existing `/plan` page now shows the main movement and up to two additional, independently editable travel legs. Added legs begin with blank local time and time zone. Each airport, station, hotel or other named place needs a selected OSM search result; quota/failure keeps the typed label and offers retry/direct confirmation. Each leg shows an unambiguous UTC conversion or an explicit DST/zone ambiguity, a selected destination country's reviewed emergency coverage and its limitations, and local walking evidence where the imported graph supports it. Longer transfers have a manual operator/property handoff and no assumed ride, transit, hotel-hour or airport-facility availability. Ask receives the same separate leg intents and country selections through an ephemeral route; incomplete legs remain incomplete, and urgent wording still yields Emergency first. A complete named additional leg can be explicitly promoted into the main Around context; the previous main leg takes its place and retains its places, time, mode and country. This selection does not start a journey or share with anyone. Live global provider coverage is not established by the browser fixtures.

## Phase 7 local implementation state (2026-10-02)

Go replaces the old Today hub at `/` and presents a direct plan/Ask choice, current tab draft, active journey and Emergency; when no journey is active, it also offers the most recent explicitly saved plan to reopen. `/today` keeps the legacy content. Journeys shows active/recent journeys, a separate temporary tab draft and signed-in account plans. Save plan requires a deliberate tap and a valid named-origin intent; it encrypts the full draft for at most 30 days, while opening one simply copies it into the editable tab plan. The account list permits deletion and shows expiry. You shows a paused legacy-habit explanation and review/delete controls; new accounts start with learning off. Phase 6 community/news facts do not enter new plan options. Automated browser checks cover primary navigation and direct Emergency; manual accessibility and comparative task results remain open.
