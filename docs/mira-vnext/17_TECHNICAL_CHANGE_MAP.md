# Technical change map for future implementation

This maps implementation and remaining change sites. Preserve user changes and inspect the working tree first. Current SQL migrations are authoritative; `src/server/db/schema.ts` is only a partial mirror.

Named origin and destination resolve by explicit selection; `from_here` is the only plan location request. Today, Around, map and Mira retain the plan across navigation. **Phase 0 test entry points:** `tests/unit/phase-zero-{contracts,urgent}.test.ts` and `tests/integration/phase-zero-{geo,journey}.test.ts` preserve the contract, urgent card, route null/failure, point deletion/link grace and purge boundary. See [Phase 0 baseline](24_PHASE_0_BASELINE.md) for actual outcomes.

**Phase 1 test entry points:** `tests/unit/phase-one-plan.test.ts` checks the draft/intent session boundary and named-origin isolation; `tests/integration/phase-one-search.test.ts` checks guest search without device coordinates; `tests/e2e/l-phase-one-plan.spec.ts` checks ambiguity, failure, back/deep-link/reload and no automatic location request. [Phase 1 result](20_ACCEPTANCE_TESTS.md) records the run. The current map route API supplies present estimates only. A future-time option or loop route is not inferred from it.

**Phase 2 implementation:** `src/domain/plan-options.ts` resolves graph eligibility, provenance, time-zone ambiguity and calculated daylight. `src/app/api/plan/options/route.ts` checks the current imported OSM graph and source snapshot, with no planned-route persistence. `src/components/app/PlanOptions.tsx` presents the same option facts in Around and map; the active plan map draws only selected graph edges. `tests/unit/phase-two-options.test.ts` and `tests/e2e/m-phase-two-options.spec.ts` cover evidence and S1–S3 display. The existing `/api/geo/route` and legacy live map remain separate; Google Routes results on a fallback non-Google map require a rights fix before that path is expanded.

**Phase 3 implementation:** `src/domain/plan-ask.ts` seeds a conservative partial draft and produces deterministic, source-bound explanations; `src/domain/urgent-intent.ts` shares the existing danger classifier between client and server without a client import of server code. `src/server/plan/options.ts` is the common request-scoped resolver. `/api/mira/plan` streams ephemeral text/card/done to guest and plan-aware signed-in Ask, with claim validation, guest IP limits and urgent bypass. `MiraChat.tsx` keeps legacy signed-in chat outside a plan; plan questions use the new route and do not enter `mira_messages`. Unit/integration/e2e Phase 3 fixtures and [privacy review](25_PHASE_3_PRIVACY_REVIEW.md) are the gate evidence.

**Phase 4 local implementation:** `src/domain/plan-journey.ts` guards selected route, time, source endpoints and fresh-origin proximity. `HomeScreen.tsx` confirms start and Circle selection. `TripScreen.tsx` reports fix/upload age and accuracy, pauses the watch while hidden, reviews OSM route evidence and confirms destination/ETA changes. `/api/trips/[id]/change` reuses the current trip record and token, verifies owner/active/4h cap and leaves recipients untouched. `UnsafeSheet.tsx` labels candidate walk time as a rough distance estimate with unverified route and staffing. `tests/unit/phase-four-journey.test.ts`, the Circle integration fixture and `tests/e2e/o-phase-four-journey.spec.ts` are local evidence; [20](20_ACCEPTANCE_TESTS.md) records the unresolved device gate.

**Phase 7 local implementation:** `GoScreen.tsx` and `TabBar.tsx` switch the root to Go/Journeys/You; `/today` and `NEXT_PUBLIC_MIRA_GO_ENTRY=legacy` provide entry rollback in a rebuilt artifact. `JourneyPlanCard.tsx` keeps a tab draft distinct from `SavedPlansList.tsx`. `/api/me/plans`, `src/server/account/saved-plans.ts`, migration `0021` and worker retention implement an explicit owner-scoped, encrypted 30-day saved plan. Migration `0020`, `src/server/account/habits.ts` and `PersonalSections.tsx` pause the old default and ask before resuming. `tests/integration/phase-seven-saved-plans.test.ts` and `companion.test.ts` cover the new privacy rules. Phase 6 sources are absent from `src/server/plan/options.ts` by design; external Phase 7 gates remain in [27](27_PHASE_7_VALIDATION_PROTOCOL.md).

**No blanket rewrite:** preserve geo/provider abstractions, route and lighting functions, Help Point candidate logic, short-trip state machine, contact/token design, privacy boundaries and worker health. A new table is justified only by an approved conceptual entity and a concrete V1 query/retention need. [Migration plan](19_MIGRATION_PLAN.md).
