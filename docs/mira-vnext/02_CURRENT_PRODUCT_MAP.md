# Current product map — implementation-backed baseline

**Method:** inspected route/page files, domain and server modules, SQL migrations, worker jobs, tests, current docs and a prior signed-out local walkthrough. Signed-in phone/device flows are code-and-test verified, not a new real-device trial. This table maps system groups; [04](04_FEATURE_DISPOSITION.md) is the definitive per-feature disposition.

**Implementation update (Phase 7, 2026-10-02):** The tables below preserve the Phase 0 baseline for comparison. Current local code makes `/` a Go intent entry with Go/Journeys/You tabs; `/today` preserves the five-tab era's Today content as a compatibility route. `/plan` is a transient guest plan, and signed-in users can explicitly save up to ten encrypted named-origin plans for 30 days under `/api/me/plans`; Go offers the latest saved plan when idle, while Journeys lists, opens and deletes them. Migrations `0020–0021` pause legacy habit learning until a choice and add saved plans. Plan-linked community/news enrichment is still disabled. No deployment or live device/provider validation is implied by this update.

**Current experience in one sentence:** a safety companion feature hub whose strongest concrete flows are checking a place/map and sharing a short journey. There is **no implemented universal safety score**. [Detailed evidence and file references](../mira-product-research/01_CURRENT_PRODUCT_AUDIT.md).

**Phase 0 verification (2026-10-02):** [the scenario baseline](24_PHASE_0_BASELINE.md) records S1–S7 as present paths versus V1 gaps. Specifically, `/api/geo/route` distinguishes unsupported ride/transit (`route:null`, HTTP 200) from a thrown provider error (HTTP 500), and current `startTripSchema` defaults an omitted `share` field to `true`. The latter is a consent gap for direct API clients against the V1 affirmative-sharing target; Phase 0 does not alter the current flow. New versioned schemas are pure contracts, not shipped planning behaviour.
