# Global availability with claim-level coverage

Global usability means a woman can state an intent and receive an honest planning path anywhere that Mira and its providers can resolve places. It does **not** mean equal local intelligence. Current country registry has 195 entries, but only 49 fully, 9 partly and 2 region-dependent reviewed emergency profiles; other country numbers remain unknown. [Generated coverage](../COUNTRY_COVERAGE.md).

## Coverage levels

| Level | Eligible user promise | Required evidence | Prohibited inference |
|---|---|---|---|
| **Planning baseline** | Intent, time/daylight, user-provided plan, available map/place/route facts, reviewed country essentials and honest unknowns. | Place resolution and each provider result state; reviewed country profile if a number is shown. | “No reports” or “no alert” means low risk. |
| **Operationally informed** | Current route/place/service details when a provider returns them, with timestamp and source. | Fresh hours/route/service response and source rights. | Listed open = staffed; a city story affects this route. |
| **Locally corroborated** | Select segment/place conditions checked by independent contributors or field operations, relevant to this time/mode. | Moderation, independence, freshness, correction operations and coverage audit. | Corroborated condition = predicted personal safety. |
| **Verified support network** | Specific access/staffing/help option claims for a bounded locale. | Recurrent physical/partner checks, routed reachability and operational owner. | Global safe-space guarantee. |

Coverage is **per claim and query**, not one badge for a country. A route can have geometry but unknown lighting; a place can have hours but unknown entry; a country can have an emergency number but no local source. Represent `ready / partial / empty / stale / failed / unavailable` distinctly. Show source and check time; a low-data answer can still compare time, distance, daylight, known official guidance and user-specified constraints. A failed provider lookup cannot be narrated as “no issue found.”

V1 must work for remote/future destinations by allowing a named origin and planned time without device location. City-by-city operations decide when locally corroborated labels are enabled. Do not enable local-verified wording based solely on a count of submissions. Third-party map content storage and display must obey provider terms. [Google Places policies](https://developers.google.com/maps/documentation/places/web-service/policies), [research](../mira-product-research/08_PRODUCT_OPPORTUNITIES.md).

**Phase 2 actual coverage:** planned walking comparisons currently use the imported pilot OSM graph only. Outside it, a query reports missing or empty graph coverage. The source snapshot is checked against a 365-day maximum age; import time does not reset freshness. Daylight is an approximate calculation where local wall time has one unambiguous instant. No future transit/ride operation, listed hours, staffing or lighting claim is inferred from a current place lookup. The legacy current-route API is separate from this planned-time resolver and still needs a broader provider display-rights remediation before expansion.

**Phase 5 actual remote baseline:** `/plan` can hold three separate movements in one two-hour tab draft. Each added leg requires its own named origin/destination selection, local departure time and IANA zone; it does not inherit the phone zone or request current GPS. A uniquely resolvable wall time is displayed as a UTC instant; DST gaps/overlaps and invalid zones are not guessed. The person chooses a destination country explicitly. `/api/plan/country` returns the existing reviewed profile with verification level, review date, limitations and source; an unverified profile returns no number. That destination profile is never presented as the phone's current emergency location. Local walking evidence is per resolved leg and only within the imported graph's 25 km query limit. Beyond it, failed place lookup, missing graph, late transport operation, hotel hours and airport/station facilities remain unknown with a direct operator/property/manual-transfer step. Browser fixtures prove the state handling; live global place/provider coverage and quotas have not been validated.
